Object Oriented Programming

What is Object Oriented Programming?

Object Oriented Programming is a model that allows code to represent real-life objects. OOP breaks down the world into different levels, which are compared in the following chart.

Classes are the broadest, most abstract level of OOP. They are unspecific templates that are used to create objects.

An instance is a specific object that is created from a class. In this case, "Maple" is an instance of the class "Tree".

Why should I care?

Many widely-used coding languages follow OOP, including Java, C++, and Javascript (Gillis, 2024). Understanding OOP is essential to understanding these languages, since the OOP format is the backbone of these languages.

Inhertiance

Now that you understand what classes and objects are, let's take a look at inheritance. Inheritance is an important concept in OOP, and is also designed to echo real life. In OOP inheritance, it is when you create subclasses (children) of a superclass (parent). In real life, when a parent gives birth to a child, the child also inherits some of the attributes of the parent - they may share eye color, habits, or physical traits. When it comes to code, a subclass will inherit any public or protected methods or fields. A subclass can also override any of these methods with its own version. This allows classes to reuse methods or fields, and further helps Java model real life objects.

Encapsulation

Another important part of OOP is encapsulation. Encapsulation allows data to be hidden from external sources, to allow something to be visible or accessible only within a certain area. For example, let’s say there’s a computer program designed to calculate and return the average mark of a class of students. A student could call on this method and correctly receive the average mark, but they wouldn’t be able to see each individual students’ marks, since that data would be encapsulated. There are three pretty basic levels of encapsulation: private, protected, and public.

Private methods and fields can only be accessed within their own class, protected data can be accessed by the original class along with any other classes related to it, such as a subclass, and public methods and fields have no protection and can be called or accessed from any class. Note that the arrows are always facing downards, since a subclass is inherits from a parent class, and not the other way around.

Usually, a class will have a mix of different levels of encapsulation to allow the class to hide data and certain functions, but also allow some level of interaction with other classes. In the example about students and their marks mentioned above, the method that calculates and returns the average would have to be public in order for the student to access it, but the student marks would likely be private. Thus, encapsulation works to hide and protect data, and only to allow certain parts of it to be visible to other classes.
